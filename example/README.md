# Worked-example artifact (`notebook-example.json`)

The committed worked example the notebook replays on `?example=1`. Produced once by
a maintainer against the **live engine** with `scripts/gen-notebook-example.ts`
(N13a); consumed **client-side** by the N13b loader.

## Files & convention

| File | Role |
|---|---|
| `notebook-example.json` | The artifact — BOTH legs (golden + judge). Shape: `src/app/notebook/example-artifact.ts`. |
| `notebook-example.json.sha256` | `sha256sum`-format sidecar: `<hex>␠␠example/notebook-example.json`. Verify with `sha256sum -c example/notebook-example.json.sha256`. |

The hash is computed over the **exact serialized bytes** (`serializeArtifact` —
pretty JSON + trailing newline). N13b's CI integrity gate fails if the artifact's
hash drifts from the sidecar without an explicit bump commit.

> Neither file is generated by the automated build. The generator **writes** them;
> a human runs it against the live engine, confirms the two teaching moments, and
> commits the result (Desk-verified, like the N1 re-seed).

## The two teaching moments (load-bearing)

The generator calls `assertTeachingConditions` and **refuses to write** unless BOTH
survive — it never silently conforms or fabricates to satisfy the shape:

1. **≥1 FAILING golden row** — the deterministic golden grade catches the live model
   getting an extraction field wrong ("a mismatch is a lead").
2. **≥1 ERRORED judge verdict** — one judge call is recorded as errored, teaching the
   "judge errored — not scored" state. An errored verdict carries **no** pass/reason;
   the generator records the absence of a ruling, never a fabricated one.

If either is missing, the generator exits non-zero with a named error
(`MissingFailingGoldenError` / `MissingErroredVerdictError`). The fix is to change the
patient selection — **not** to edit a golden or invent a verdict.

## Zero-metered-call replay contract (for N13b)

Opening the worked example spends **nothing** of either model:

- **Golden leg** — the grade is DETERMINISTIC. The artifact stores the captured
  `output` + hand-authored `golden`; the loader recomputes the verdict with
  `replayGoldenGrade` (pure). No verdict is stored, so the painted line can't drift
  from the committed inputs.
- **Judge leg** — the criteria verdict was a metered call at generation time, so its
  `{pass, reason}` is RECORDED and replayed verbatim with `replayJudgeVerdict`; the
  judge is never re-called. Errored verdicts replay to the "not scored" state.

See the contract block at the top of `src/app/notebook/example-artifact.ts`.

## Regenerating (maintainer, manual)

1. Pin real seeded patient ids + author **truthful** goldens in
   `evals/golden/notebook-example-seed.json`.
2. `ANTHROPIC_API_KEY=… DATABASE_URL=… npm run gen:notebook-example`
3. Confirm the printed teaching-moment summary (≥1 failing golden, ≥1 errored verdict).
4. Commit `notebook-example.json` + `notebook-example.json.sha256`.
